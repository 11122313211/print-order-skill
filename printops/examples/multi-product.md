# 示例：多产品拆单与未知品类分叉

何时读：用户一句话里出现**多种印刷品**，或要印的东西不在 18 类品类清单里。

## 场景 A：多产品拆单（500 张名片 + 200 个纸杯）

用户说——「做500张名片和200个纸杯」

### 第 1 步：ingest 检测到多产品

```bash
$CLI ingest --text "做500张名片和200个纸杯"
```

```json
{
 "multiProduct": true,
 "hint": "检测到多个印刷品。请为每种产品分别建单：对同一句需求分别执行 ingest，各指向不同的 --file 并加 --pick-item 0 / --pick-item 1；之后的追问、方案和交接单也按订单文件分别进行。"
}
```

### 第 2 步：按 hint 拆单——同一句原话，两个订单文件

```bash
$CLI ingest --file 名片.json --text "做500张名片和200个纸杯" --pick-item 0
# → order.productType = "名片"，quantity = "500 张"
$CLI ingest --file 纸杯.json --text "做500张名片和200个纸杯" --pick-item 1
# → order.productType = "纸杯"，quantity = "200 个"
```

### 第 3 步：两条线独立推进

名片.json 和 纸杯.json **各自**走追问 → recommend → select → price → handoff
（对 `$CLI` 加 `--file 名片.json` / `--file 纸杯.json` 指向对应订单）。
规则引擎会直接拦截合并估价与合并交接单——不要尝试把两个品类拼进一张报价或一张交接单。
对话里可以并排汇报两条线的进度，但每个品类的数字只引用它自己订单文件的输出。

## 场景 B：未知品类分叉（纸模型摆件）

用户说——「我想印100个小熊纸模型摆件」

`ingest` 认不出品类（或 `catalog` 清单里没有）。先分叉判断，**不要急着套品类**：

- **平面载体上的图案**（异形贴纸、造型卡片）：按最接近的平面品类整理参数，
  但明确说"这是按最近品类的假设"，形状/模切字段标注"需供应商确认"；
- **立体造型件**（本例：纸模型摆件）：**不硬塞进任何品类**——会污染订单字段。
  如实说明超出批量印刷品类范围，给出可行路线：打样件（1 件口径，不说成批量印刷）、
  数码快印、写真喷画、手工制作。

用户坚持按最近品类下单时：订单里保留假设标注并注明"待供应商确认"，
不要把假设说成事实。三条铁律（参考费用注明、交接单只是草稿、弱推断必须确认）
在未知品类场景同样全程生效。
